# gym_analytics

О проекте

gym_analytics — учебный аналитический проект, моделирующий информационную систему спортивного зала.

Проект рассматривает полный путь работы с данными: бизнес-процесс → модель данных → база данных → SQL-запросы → аналитические показатели → визуализация → бизнес-выводы.

Основная задача — показать, как автоматизация операционных процессов и структурированное хранение данных позволяют сократить ручной труд сотрудников и получать управленческую информацию на основе данных.

В рамках проекта рассматривается работа с:

клиентами спортивного зала;
абонементами;
типами абонементов;
ценами;
статусами абонементов;
посещениями;
входами и выходами клиентов;
аналитикой выручки;
загрузкой зала.

Цель проекта

Разработать концепцию автоматизированной системы учёта посещений спортивного зала и создать аналитическую часть системы, позволяющую руководству получать информацию о клиентах, абонементах, посещаемости и выручке.

Основные задачи
Проанализировать существующий бизнес-процесс.
Определить проблемы ручного учёта посещений.
Разработать модель процессов AS-IS / TO-BE.
Спроектировать реляционную базу данных.
Нормализовать структуру данных до 3НФ.
Создать SQL-скрипты для работы с базой.
Разработать аналитические SQL-запросы.
Рассчитать ключевые бизнес-показатели.
Подготовить данные для визуализации.
Создать аналитический дашборд в Power BI.


Бизнес-проблема

В исходном сценарии учёт посещений спортивного зала осуществляется вручную с использованием Excel.

Такой подход приводит к нескольким проблемам:

поиск клиента осуществляется вручную;
увеличивается время обслуживания посетителей;
возрастает вероятность ошибок при проверке абонемента;
регистрация посещений требует ручных действий;
формирование отчётности занимает значительное время;
управленческая информация не формируется оперативно.
AS-IS

Текущий процесс можно представить следующим образом:

Клиент приходит в зал
        ↓
Поиск клиента
        ↓
Проверка абонемента
        ↓
Проверка статуса
        ↓
Регистрация посещения
        ↓
Ручное обновление данных
        ↓
Формирование отчётности

Предлагаемое решение

Предлагается автоматизированная информационная система, в которой данные о клиентах, абонементах и посещениях хранятся в централизованной базе данных.

TO-BE
Клиент
   ↓
Идентификация
   ↓
Проверка абонемента
   ↓
Автоматическая проверка статуса
   ↓
Регистрация посещения
   ↓
Сохранение в БД
   ↓
SQL-аналитика
   ↓
Power BI
   ↓
Управленческие решения

В концепции системы предусмотрено использование штрих-кода для идентификации клиента и автоматизированного контроля доступа.

Функционально-временной анализ

Для оценки эффекта автоматизации проведено сравнение трудозатрат до и после внедрения системы. Результат

Расчётный эффект:

5 400 минут экономии в месяц;
90 часов высвобождённого рабочего времени;
снижение трудозатрат на 81,8%;
сокращение времени выполнения рассматриваемых операций примерно в 5,5 раза.

Показатели являются расчётной оценкой эффекта автоматизации в рамках учебного бизнес-кейса.

Таблицы базы данных:

clients - Данные клиентов
membership_types - Справочник типов абонементов
memberships	- Абонементы клиентов
membership_prices	- История цен на абонементы
status_types	- Справочник статусов абонементов
membership_statuses	- История изменения статусов
movement_types	- Тип движения: вход / выход
visits	- История посещений

Основные связи

Клиент → Абонемент

Один клиент может иметь один или несколько абонементов.

Тип абонемента → Абонемент

Каждый абонемент относится к определённому типу.

Тип абонемента → Цена

Для типов абонементов хранится информация о стоимости.

Абонемент → Посещения

Каждое посещение связано с конкретным абонементом.

Посещение → Тип движения

Для посещения определяется направление движения:
вход;
выход.

SQL-аналитика

SQL используется не только для создания структуры базы данных, но и для получения бизнес-показателей.

В проекте подготовлены отдельные SQL-скрипты для различных аналитических задач.

Основные аналитические вопросы
1. Какая выручка приходится на каждый тип абонемента?

Позволяет определить:

какие абонементы продаются чаще;
какие типы формируют большую выручку;
какие продукты могут быть наиболее значимыми для бизнеса.

Пример запроса:

SELECT
    mt.name AS Тип_абонемента,
    mp.price AS Цена,
    COUNT(m.membership_id) AS Продано_абонементов,
    mp.price * COUNT(m.membership_id) AS Общая_выручка
FROM membership_types mt
JOIN membership_prices mp
    ON mt.membership_type_id = mp.membership_type_id
JOIN memberships m
    ON mt.membership_type_id = m.membership_type_id
GROUP BY
    mt.membership_type_id,
    mt.name,
    mp.price
ORDER BY Общая_выручка DESC;
2. Как клиенты используют свои абонементы?

Запрос позволяет определить:

количество посещений;
количество входов;
количество выходов;
наиболее активных клиентов;
распределение посещаемости между клиентами.


SELECT
    c.last_name || ' ' || c.first_name AS Клиент,
    mt.name AS Тип_абонемента,
    COUNT(v.visit_id) AS Количество_посещений,
    SUM(
        CASE
            WHEN v.movement_type_id = 1 THEN 1
            ELSE 0
        END
    ) AS Входов,
    SUM(
        CASE
            WHEN v.movement_type_id = 2 THEN 1
            ELSE 0
        END
    ) AS Выходов
FROM clients c
JOIN memberships m
    ON c.client_id = m.client_id
JOIN membership_types mt
    ON m.membership_type_id = mt.membership_type_id
LEFT JOIN visits v
    ON m.membership_id = v.membership_id
GROUP BY
    c.client_id,
    c.last_name,
    c.first_name,
    mt.name
ORDER BY Количество_посещений DESC;
3. Кто является клиентами зала и какие абонементы они используют?

Запрос объединяет информацию о клиенте и его абонементе:

SELECT
    c.last_name || ' ' ||
    c.first_name || ' ' ||
    c.middle_name AS ФИО,
    c.phone AS Телефон,
    c.email AS Email,
    mt.name AS Тип_абонемента,
    m.issue_date AS Дата_оформления
FROM clients c
JOIN memberships m
    ON c.client_id = m.client_id
JOIN membership_types mt
    ON m.membership_type_id = mt.membership_type_id
ORDER BY m.issue_date DESC;
