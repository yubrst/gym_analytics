# gym_analytics

# ️ Автоматизированная система учёта посещений спортивного зала

> **Бизнес-результат:** Сокращение трудоёмкости процесса учёта посещений с **6600 до 1200 минут в месяц** (ускорение в **5.5 раза**, экономия **81.8%** времени администратора).

Проект по автоматизации бизнес-процессов спортивного зала: от моделирования процессов (IDEF0, DFD) и проектирования реляционной базы данных до разработки desktop-приложения, аналитических SQL-запросов и интерактивного дашборда в Power BI.

---

## Цель и результаты проекта

**Проблема (AS-IS):** Ручной учёт посещений в MS Excel приводит к:
- Очередям на ресепшен (поиск клиента по фамилии вручную)
- Ошибкам человеческого фактора (неверная проверка статуса абонемента)
- Высоким трудозатратам (6600 минут/месяц = 110 часов работы администратора)
- Задержкам в получении управленческой отчётности

**Решение (TO-BE):** Внедрение Автоматизированной информационной системы (АИС) со:
- Сканером штрих-кодов для мгновенной идентификации клиента
- Турникетом с автоматическим контролем доступа
- Централизованной базой данных (MySQL/SQLite)
- Дашбордами для аналитики в реальном времени

###  Функционально-временной анализ (ФВА)

| Показатель | AS-IS (мин/мес) | TO-BE (мин/мес) | Эффект |
|---|---|---|---|
| Идентификация клиента | 900 | 150 | **-83%** |
| Проверка статуса абонемента | 1200 | 300 | **-75%** |
| Регистрация посещения | 1500 | 150 | **-90%** |
| Формирование отчётности | 3000 | 600 | **-80%** |
| **ИТОГО** | **6600** | **1200** | **-81.8%** |

**Экономия:** 5400 минут (90 часов) работы администратора в месяц.

## 🗄 Архитектура базы данных

База данных спроектирована в **Третьей нормальной форме (3НФ)** и состоит из 8 таблиц:

| Таблица | Описание | Записей |
|---|---|---|
| `clients` | Клиенты зала (ФИО, телефон, email, штрих-код) | 5 |
| `membership_types` | Справочник типов абонементов | 4 |
| `memberships` | Абонементы клиентов (составной PK) | 5 |
| `membership_prices` | История изменения цен | 4 |
| `status_types` | Справочник статусов (Активен, Заморожен, Просрочен, Исчерпан) | 4 |
| `membership_statuses` | Журнал изменений статусов абонементов | 5 |
| `movement_types` | Виды движения (Вход/Выход) | 2 |
| `visits` | Посещения зала | 15 |


##  Аналитика и визуализация данных

Проект включает полный цикл аналитической работы: от написания SQL-запросов до построения интерактивных дашбордов.

### Аналитические SQL-запросы

Разработаны SQL-запросы для формирования ключевых бизнес-отчётов:

1. Выручка по типам абонементов
```sql
SELECT 
    mt.name AS Тип_абонемента,
    mp.price AS Цена,
    COUNT(m.membership_id) AS Продано_абонементов,
    mp.price * COUNT(m.membership_id) AS Общая_выручка
FROM membership_types mt
JOIN membership_prices mp ON mt.membership_type_id = mp.membership_type_id
JOIN memberships m ON mt.membership_type_id = m.membership_type_id
GROUP BY mt.membership_type_id, mt.name, mp.price
ORDER BY Общая_выручка DESC;

2. Статистика посещений по клиентам

SELECT 
    c.last_name || ' ' || c.first_name AS Клиент,
    mt.name AS Тип_абонемента,
    COUNT(v.visit_id) AS Количество_посещений,
    SUM(CASE WHEN v.movement_type_id = 1 THEN 1 ELSE 0 END) AS Входов,
    SUM(CASE WHEN v.movement_type_id = 2 THEN 1 ELSE 0 END) AS Выходов
FROM clients c
JOIN memberships m ON c.client_id = m.client_id
JOIN membership_types mt ON m.membership_type_id = mt.membership_type_id
LEFT JOIN visits v ON m.membership_id = v.membership_id
GROUP BY c.client_id, c.last_name, c.first_name, mt.name
ORDER BY Количество_посещений DESC;

3.Все клиенты с абонементами

SELECT 
    c.last_name || ' ' || c.first_name || ' ' || c.middle_name AS ФИО,
    c.phone AS Телефон,
    c.email AS Email,
    mt.name AS Тип_абонемента,
    m.issue_date AS Дата_оформления
FROM clients c
JOIN memberships m ON c.client_id = m.client_id
JOIN membership_types mt ON m.membership_type_id = mt.membership_type_id
ORDER BY m.issue_date DESC;
