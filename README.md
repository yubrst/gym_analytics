# gym_analytics

Учебный проект по анализу и автоматизации процесса учёта посещений спортивного зала.

Проект охватывает полный цикл работы с задачей: анализ текущего бизнес-процесса → моделирование AS-IS / TO-BE → проектирование базы данных → SQL-аналитика → визуализация данных в Power BI.

Расчётный эффект автоматизации: трудоёмкость процесса снижается с 6600 до 1200 минут в месяц — на 81,8%. Показатель получен в рамках функционально-временного анализа модели TO-BE и не является результатом фактического внедрения системы.

О проекте

В исходном процессе учёт посещений спортивного зала выполняется вручную. Администратору необходимо идентифицировать клиента, проверить состояние его абонемента, зарегистрировать посещение и подготовить отчётность.

Такой подход приводит к дополнительным трудозатратам и увеличивает зависимость процесса от ручных операций.

В рамках проекта разработана модель автоматизированной информационной системы, которая предполагает:

автоматическую идентификацию клиента;
проверку статуса абонемента;
регистрацию входов и выходов;
централизованное хранение данных;
формирование аналитической отчётности.

Цели проекта
Проанализировать существующий процесс учёта посещений.
Выявить основные ручные операции и связанные с ними трудозатраты.
Разработать модель автоматизированного процесса.
Спроектировать реляционную базу данных.
Подготовить SQL-запросы для получения аналитической информации.
Представить результаты анализа в интерактивном Power BI-дашборде.

Моделирование бизнес-процессов

Для описания предметной области использовались IDEF0 и DFD.

AS-IS

Текущий процесс включает четыре основных этапа:

Идентификация клиента.
Проверка статуса абонемента.
Регистрация посещения.
Формирование статистики посещений.

Функционально-временной анализ показал общую трудоёмкость процесса 6600 минут в месяц при расчётной нагрузке в 300 посещений.

TO-BE

В целевой модели рутинные операции передаются автоматизированной системе.

Предусмотрены:

автоматизированная идентификация клиента;
автоматическая проверка абонемента;
автоматическая регистрация посещения;
автоматическое формирование статистики;
использование штрих-кода для идентификации;
централизованная база данных;
аналитическая отчётность.

Модели процессов представлены в папке gym project.

Функционально-временной анализ
Операция	AS-IS, мин/мес	TO-BE, мин/мес	Изменение
Идентификация клиента	900	150	−83%
Проверка абонемента	1200	300	−75%
Регистрация посещения	1500	150	−90%
Формирование отчётности	3000	600	−80%
Итого	6600	1200	−81,8%

Расчётный эффект:

экономия — 5400 минут в месяц;
это соответствует 90 часам;
расчётное ускорение процесса — 5,5 раза.

Важно: показатели являются результатом моделирования AS-IS / TO-BE и используются для оценки потенциального эффекта автоматизации.

Проектирование базы данных

Для хранения информации разработана реляционная модель данных.

База содержит 8 основных таблиц:

Таблица	Назначение
clients	информация о клиентах
membership_types	типы абонементов
memberships	абонементы клиентов
membership_prices	цены на абонементы
status_types	справочник статусов
membership_statuses	история статусов абонементов
movement_types	типы движения: вход / выход
visits	информация о посещениях

При проектировании учитывались связи между сущностями, первичные и внешние ключи, а также нормализация структуры данных.

SQL и аналитика

В проекте разработаны SQL-запросы для получения бизнес-метрик и формирования отчётности.

Выручка по типам абонементов

Запрос позволяет определить:

тип абонемента;
его стоимость;
количество проданных абонементов;
общую выручку по каждому типу.
Статистика посещений

Рассчитываются:

количество посещений клиента;
количество входов;
количество выходов;
тип абонемента клиента.
Данные о клиентах

Формируется выборка клиентов с информацией об:

ФИО;
телефоне;
email;
типе абонемента;
дате оформления.
Дополнительная аналитика

В репозитории также представлены SQL-запросы для анализа загрузки спортивного зала по датам.

Визуализация

Для визуального представления аналитических данных использован Power BI Desktop.
